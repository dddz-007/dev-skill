# dev-skill 使用案例

以下示例假设 `dev-skill` 已安装。Cursor 使用 `/dev-skill`，Codex 使用 `$dev-skill`。

## 一、首次接入项目
```text
/dev-skill
这是一个新的项目协作会话。请先读取项目规则和文档，执行调查和方案阶段，不要立即修改代码或数据库。
本次需求：
[填写需求]
```

## 二、新需求：前端、后端、数据库都要新增
```text
/dev-skill
需求名称：用户标签管理
需求描述：管理员可新增、编辑、删除标签，并在用户详情页绑定多个标签。
验收标准：支持新增/编辑/删除/绑定；普通用户无权访问；刷新后数据仍存在。
范围：全部
环境：测试
数据库操作授权：允许建表
请先调查和制定方案，输出表设计、前向/回滚 SQL、接口协议、文件清单、风险和测试方案。高风险操作必须暂停等待确认。
```

## 三、已有功能修改：前端、后端、数据库都有内容
```text
$dev-skill
需求名称：订单状态增加“已取消”
现状：前端有订单列表，后端有订单接口，数据库有 orders 表。
要求：保留历史状态和旧接口兼容，说明状态流转、历史数据兼容和回滚方式。
范围：全部
环境：测试
数据库操作授权：允许改表
先只读检查现有代码、接口和表结构，再给方案。任何批量修改历史订单或破坏接口兼容的操作，先风险提示并等待确认。
```

## 四、只修改前端
```text
/dev-skill
请修复用户列表分页问题：点击第 2 页后仍显示第 1 页数据。
范围：前端
约束：不修改后端和数据库，尽量小范围修改。完成后做前端静态检查、构建或相关测试，并说明修改文件和证据。
```

## 五、只修改后端
```text
/dev-skill
请为现有商品查询接口增加按商品名称模糊查询。
范围：后端
约束：保持现有响应结构和数据库结构不变。检查参数校验、权限和索引使用，完成后运行后端测试并给出接口调用示例。
```

## 六、只修改数据库
```text
$dev-skill
需求：为 products 表增加可选的 display_order 字段。
范围：数据库
环境：测试
数据库操作授权：只读（只生成脚本，不连接或执行变更）
请检查表结构，生成前向 SQL、回滚 SQL、备份建议、Navicat 执行步骤和验证查询；不要修改前后端，也不要声称数据库已变更。
```

## 七、纯界面或文案调整
```text
/dev-skill
请把用户详情页的“创建时间”改成“注册时间”，接口、数据和其他样式保持不变。只改必要文件，完成前端检查并给出简短总结。
```

## 八、问题修复且可能影响历史数据
```text
$dev-skill
现象：用户修改手机号后，部分旧订单查询不到。
请先只读分析前后端和数据库关联关系。若需要修改历史数据，必须先输出风险等级、影响行数估算、备份和回滚方案，然后暂停等待确认。
```

## 九、只做代码审查，不修改
```text
/dev-skill
请审查当前工作区的实际 Diff。本轮只审查，不修改。检查需求覆盖、复用、修改范围、公共接口、编码、编译、测试、数据库风险、权限安全和视觉结果。按风险等级列出问题，并说明未检查项目及原因。
```

## 十、只做方案或 SQL，不执行
```text
/dev-skill
请只分析需求并输出实施方案和数据库前向/回滚 SQL。本轮禁止修改代码、禁止执行数据库变更。给出影响、备份要求、验证查询和 Navicat 手工步骤。
```

## 十一、无法启动或无法连接数据库
```text
/dev-skill
当前后端无法启动且无法连接数据库。只分析可访问资料，生成待执行脚本和手工验证步骤，不得声称已联调、已建表或已完成；将状态标记为部分完成或被阻塞，并列出需要补充的内容。
```

## 十二、继续上次未完成任务
```text
$dev-skill
继续上次任务。先查看当前工作区实际改动和未完成项，不要重复已完成修改。若仍在等待确认，只报告待确认的具体操作和环境，等待我的明确确认。
```
